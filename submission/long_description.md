# WorldReady — Problem & Solution

**The problem.** Taking a product to a new market is a *code* problem, not a translation problem. Quebec's Bill 96 requires French; growth in the Gulf and wider MENA requires Arabic — and Arabic means right-to-left layout, six plural forms, and Eastern number and date formatting. Machine translation cannot fix any of the traps that actually break a localized app: strings hard-coded in JSX, glued plurals ("1 seats left"), physical `left`/`right` layout that should mirror, and English baked into data files and toast messages. Worse, the retrofit is never "done" — one hard-coded string added later silently ships broken UI. We measured a real English-only app (Galaxium Travels, Apache-2.0): **305 hard-coded user-visible strings, one language, `<html lang="en">` with no `dir`, and 12 physical left/right layout classes.**

**The solution.** WorldReady is an IBM Bob–driven internationalization retrofit that turns that app into **English + French (Québec) + Arabic (RTL)** — and then installs a gate that keeps new English out. Bob extracts every user-visible string into i18next keys (five parallel subagents, one per app area), wires real i18n (Intl number/date/relative-time, CLDR plurals including Arabic's six categories, logical RTL utilities, mirrored icons, Noto Sans Arabic), produces a translator round-trip spreadsheet for native review, and adds a **PreToolUse commit hook + GitHub Actions gate** that fails the build on any new hard-coded string.

**Target users & how they interact.** Product and platform teams entering regulated or RTL markets, and agencies retrofitting client apps. They run Bob's `i18n-extractor` mode over their repo, review machine-draft translations in the round-trip sheet, and merge — after which the gate protects every future PR. Judges and reviewers interact through a **live comparison viewer**: flip the language picker to العربية and the whole app mirrors to RTL; press *Scan* and hard-coded English is outlined in both panes — **Before: many, After: 0** — with a six-form Arabic plural showcase rendered from the real shipped bundle.

**Why it is unique.** Alternatives — Lingo.dev, i18next-parser, Crowdin — help you *extract* or *translate*; none retrofit the code traps (plurals, formatting, RTL, data & toasts) **and** install a regression gate in one Bob-driven pass. Our line: *TransCreate localizes developer videos; WorldReady localizes app code — keys, plurals, formatting, RTL, and a gate. Accessibility tools such as Usher and CurbCut ask whether everyone can use the app; WorldReady asks whether every market can.*

**Measured impact (independent verifiers, not estimates).** Hard-coded user-visible English **305 → 0**; **24 / 30** engineered i18n traps fixed, scored against a held-out key whose SHA-256 was committed *before any Bob task ran*; **0 characters** of existing English content changed; **1 → 3** languages plus a pseudo-locale; locale key-parity **PASS**. Built end-to-end in IBM Bob 2.0 across 17 tasks (17.67 of 40 Bobcoins); every session exported in `bob_sessions/`. Live: https://chinmoypaul8897.github.io/worldready/
